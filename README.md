## Описание проектов

### 1. Каталог товаров — product-service
*   **Папка в репозитории:** [`product-service`](./product-service)
*   **Цель проекта:** Провести функциональное тестирование каталога товаров, проверить работу пагинации, фильтрации, сортировки, поиска и детализации товаров.
*   **Объект тестирования (3 эндпоинта):**
    *   `GET /api/products` — просмотр списка товаров
    *   `GET /api/products/search` — поиск товаров
    *   `GET /api/products/{id}` — детализация товара
*   **Условия тестирования:**
    *   **Окружение:** localhost (локальный запуск через Docker Compose)
    *   **URL сервиса:** `http://localhost:8082`
    *   **Инструмент:** Postman
    *   **Документация:** Составлен чек-лист из 252 тестов, покрывающий все требования
*   **Результаты и выводы:**
    *   **Метрики:** Из **252 тестов** успешно пройдено **45**, обнаружено **24 дефекта**, **183 теста** пропущено.
    *   **Трудоемкость:** Тестирование проводилось с 22.05.2026 по 02.06.2026.
    *   **Найденные дефекты:** 11 (BUG-PS-1 — BUG-PS-11)
    
    **Распределение дефектов по приоритету:**
    | Приоритет | Количество |
    |-----------|------------|
    | Блокирующий | 1 |
    | Высокий | 8 |
    | Низкий | 2 |
    
    **Ключевые проблемы:**
    *   **Блокирующий баг:** Не работает поиск товаров (`BUG-PS-10`)
    *   Не работает пагинация: `page=1` возвращает вторую страницу вместо первой
    *   Не работает сортировка по цене и названию
    *   Не работает фильтрация по категории, бренду и диапазону цен
    *   Не работает смещение (`offset`)
    *   Параметр `size` вместо `limit` — не соответствует документации
    *   При указании пробела в параметре `size` возвращается 200 OK (должен быть 400)
    *   При указании ID товара с пробелом возвращается 200 OK (должен быть 400)
    *   Неинформативные ошибки при невалидных параметрах
    
    **Анализ:** Обнаружен **блокирующий баг**, который делает невозможным поиск товаров, а также 8 высокоприоритетных дефектов, полностью нарушающих работу с каталогом (фильтрация, сортировка, пагинация).
    
    **Итоговая рекомендация:** **Продукт выпускать не рекомендуется** до полного устранения блокирующего дефекта и исправления 8 высокоприоритетных проблем. После исправлений необходимо провести полное регрессионное тестирование всех 252 проверок.

### 2. Оформление заказов — order-service
*   **Папка в репозитории:** [`order-service`](./order-service)
*   **Цель проекта:** Провести функциональное тестирование оформления заказов, проверить создание заказа, просмотр истории и детализацию.
*   **Объект тестирования (3 эндпоинта):**
    *   `POST /api/orders` — создание заказа
    *   `GET /api/orders` — просмотр истории заказов
    *   `GET /api/orders/{id}` — детализация заказа
*   **Условия тестирования:**
    *   **Окружение:** localhost (локальный запуск через Docker Compose)
    *   **URL сервиса:** `http://localhost:8084`
    *   **Инструмент:** Postman
    *   **Документация:** Составлен чек-лист из 109 тестов
*   **Результаты и выводы:**
    *   **Метрики:** Из **109 тестов** успешно пройден **1**, обнаружено **0 дефектов**, **108 тестов** пропущено.
    *   **Трудоемкость:** Тестирование проводилось с 22.05.2026 по 30.05.2026.
    *   **Найденные дефекты:** 1 блокирующий баг в смежном сервисе (BUG-CART-1)
    
    **Ключевые проблемы:**
    *   **Блокирующий баг:** Невозможно создать заказ из-за невозможности добавить товар в корзину (`BUG-CART-1` в cart-service)
    *   cart-service не может зарезервировать stock в product-service (Feign-запрос получает 403 Forbidden)
    *   Единственный успешный тест — создание заказа с пустой корзиной (`OS-11` → 400 Bad Request)
    
    **Анализ:** Модуль полностью заблокирован и не может быть полноценно протестирован до исправления смежного сервиса. Без работающей корзины проверка заказов невозможна.
    
    **Итоговая рекомендация:** **Продукт выпускать не рекомендуется**. Необходимо сначала исправить `BUG-CART-1` в cart-service, после чего провести полное перетестирование всех 109 проверок.

## Технологии и инструменты

*   **Postman** — ручное тестирование API, создание коллекций запросов
*   **Docker Compose** — локальное развертывание микросервисов
*   **PostgreSQL** — проверка данных в базе (контейнеры product-db)
*   **Google Sheets / Excel** — составление чек-листов и баг-репортов
*   **Swagger/OpenAPI** — документация API (заявлена, но не предоставлена)
*   **macOS / Windows 11** — тестовые окружения
